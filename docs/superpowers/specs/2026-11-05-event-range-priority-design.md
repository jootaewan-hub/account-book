# 일정 넣기 칸, 기간 일정, 중요도 효과 (D-054, v2.30.0)

2026-11-05 사용자: "일정을 생성하는데 일정 생성 칸이 뚜렷하게 보이지 않아 그걸 잘 보이게 만들고, 일정 생성할 때 구간 설정이 안 되니 몇 월 며칠에서 몇 월 며칠까지 설정이 가능하도록 하고, 일정별로 중요도를 이펙트로 구분할 수 있도록 여러 이펙트를 구현해서 선택할 수 있도록". 자동 모드라 설계는 구현자가 정했다(아래 "정한 것과 까닭").

## 지금까지

- 달력 고른 날 아래의 넣기는 세이지 글자 버튼 둘("일정·기념일 넣기", "캡처·문자로 일정 넣기")뿐이었다. 면도 테두리도 없어 내역 줄 사이에서 눈에 띄지 않았다.
- 일정(`public.events`)은 날짜 하나(`date`)와 시간(선택)만 있다. 여행·출장처럼 여러 날 이어지는 일은 날마다 따로 넣어야 했다.
- 일정은 모두 같은 세이지 면으로 보여, 꼭 챙길 일과 그렇지 않은 일이 구별되지 않았다(누구 일정인지만 띠·태그로 구별, D-044).

## 하는 것

### 1. 일정 넣기 칸 (`CalendarView`의 `DayNew`)

- 고른 날의 일정·기념일 줄 아래, 내역 위에 귀리 면 묶음(모서리 12px)을 둔다: 제목 "11월 5일에 일정 넣기"(14px 700) → 흰 입력칸(먹 10% 선, 자리 글 "예: 치과 예약, 가족 여행") + 먹색 "넣기" → 13px 안내 → 흰 보조 버튼 둘("자세히 넣기", "캡처·문자로 넣기").
- 이름만 적고 "넣기"(또는 Enter)를 누르면 그날의 하루 종일·함께·보통 일정으로 바로 들어가고 칸을 비운다. 비어 있으면 넣지 않고 칸 테두리를 클레이로 바꾸며 "일정 이름을 적어 주세요."를 알린다(색만으로 알리지 않는다).
- "자세히 넣기"는 일정·기념일 시트를 연다(적던 이름을 가져간다). 시간·기간·중요도·장소·기념일은 여기서 정한다.
- 색이 아니라 면(귀리)·테두리(먹 10%)·자리(일정 줄 바로 아래)·제목으로 구별한다. 묶음은 화면 흐름 안에 있어 아래 탭에 가리지 않는다.

### 2. 기간 일정

- DB: `events.end_on date`(끝나는 날, 그날 포함, 하루 일정은 null). 검사 `events_range_check`: 시작보다 앞일 수 없고 366일을 넘지 않는다. 마이그레이션 `20261115000000_event_range_priority.sql`.
- 읽기(`fetchEvents`): 보는 기간에 걸친 일정 = 시작이 기간 끝 이전이고, 시작이나 끝이 기간 처음 이후. 앞 달에 시작해 이번 달에 끝나는 일정도 들어온다.
- 폼(`PlanSheet`의 `EventForm`): "시작하는 날" · "끝나는 날 (선택)" 두 칸. 그 아래 한 줄이 "하루 일정이에요…" / "**11월 7일 ~ 9일**, 3일 동안" / 까닭(끝이 시작보다 앞, 1년 넘김)으로 바뀐다. 까닭이 있으면 끝 칸 테두리가 클레이, "넣기"는 꺼진다(날짜를 몰래 고치지 않는다). "끝나는 날 지우기"로 하루 일정으로 돌린다. 끝이 시작과 같으면 하루 일정(null)으로 넣는다. 시간 칸은 기간 일정이면 "시작 시간".
- 달력 칸: 기간 안의 날마다 이름을 보인다(`eventsByDate`). 이웃 날과 이어지는 쪽은 모서리를 펴고 칸 끝까지 붙여 한 띠로 보이게 한다(첫날 `r-start`, 가운데 `r-mid`, 마지막 날 `r-end`). 남편·아내 띠는 첫날과 줄이 바뀐 첫 칸(일요일·1일, `r-head`)에만.
- 고른 날 줄: 오른쪽에 "11월 7일 ~ 9일"(시간이 있으면 ", 14:00"). 달이 다르면 "11월 28일 ~ 12월 2일", 해가 다르면 연도까지. 칸 읽기 이름은 "가족 여행(꼭, 11월 7일 ~ 9일)".
- 다가오는 일정: 칩에 기간을 적고, 이미 시작해 오늘도 이어지면 D-day 대신 "하는 중"(누르면 오늘로 간다). 끝난 일정은 뺀다.

### 3. 중요도와 효과

- DB: `events.priority`(normal·high·must = 보통·중요·꼭, 기본 normal), `events.effect`(outline·fill·breathe·mark·bold, 기본 outline). 둘 다 일정마다 두어 배우자 화면에도 같게 보인다. 보통 일정은 효과를 쓰지 않는다.
- 폼: "중요도" 세 칸. 중요·꼭을 고르면 "달력에 보일 효과" 다섯 칸이 나오고, 칸마다 지금 적은 일정 이름을 달력 칸 이름 모양으로 미리 보인다(고른 중요도에 맞춰). 고른 칸은 먹색 2px 테두리와 굵은 이름. 마지막으로 고른 효과는 기기에 기억해(`ab:lastEventEffect`) 다음 일정의 처음 값으로 쓴다.
- 효과(중요 / 꼭): 테두리(1px / 먹색 2px), 채움(세이지 면 / 먹색 면, 글자는 버튼 글자색), 숨쉬기(면 위 같은 색 막의 투명도 0.04↔0.3, 한 방향 2.8초 / 1.6초 + 먹색 1px 테두리), 점·별(이름 앞 점 / Phosphor star-fill), 굵은 글자(먹색 700 / + 밑줄).
- 보이는 곳: 달력 칸 이름, 고른 날 줄(장소가 있으면 장소 줄까지 묶은 면), 다가오는 칩, 폼 미리보기. 달력 칸은 꼭 → 중요 → 보통 순서로 두 개까지 보여 중요한 일정이 "+N"에 숨지 않는다(기념일 먼저는 그대로, D-043).
- 색·움직임만으로 알리지 않는다: 고른 날 줄과 칩에는 "중요"·"꼭" 글자 태그가 늘 붙고, 달력 칸은 읽기 이름에 적는다. 효과마다 색 아닌 단서(선 굵기, 명암, 표시, 굵기·밑줄)가 있다.
- 움직임 규칙: 숨쉬기만 움직인다. 글자와 돈 숫자는 움직이지 않고(막의 투명도만), 곡선은 `cubic-bezier(0.45, 0, 0.55, 1)`(ease-in 아님), `prefers-reduced-motion`이면 멈추고 테두리(1px / 2px)로 바꿔 구별을 남긴다.

## 정한 것과 까닭

- **효과를 일정마다 DB에 둔다**(설정에서 한 번 고르는 방식 대신). 사용자 말이 "일정별로 … 이펙트 … 선택"이고, 기기 설정으로 두면 배우자 화면과 모양이 달라진다. 매번 고르는 번거로움은 마지막 효과 기억으로 줄였다.
- **넣기 칸에 진짜 입력칸을 둔다**. 사용자가 "일정 생성 칸"이라고 불렀고, 버튼만 키우는 것보다 그 자리에서 바로 적는 편이 가장 자주 하는 일(이름만 있는 하루 일정)에 맞다. 자세한 것은 시트로 보낸다.
- **기간 안의 날마다 이름을 적는다**(첫날에만 적고 띠만 잇지 않는다). 칸마다 보이는 이름이 두 개로 제한되고 기념일이 먼저라 날마다 줄 위치가 달라질 수 있어, 띠만으로는 무슨 일정인지 알기 어렵다.
- **기간 상한 366일**. 끝 날짜를 잘못 적어(연도 오타) 달력 칸마다 이름이 깔리는 것을 DB와 폼에서 함께 막는다.
- **고른 날 줄은 시간 순서 그대로**, 달력 칸만 중요도 순서. 줄은 다 보이므로 읽는 순서(시간)를 지키고, 칸은 두 개 제한 때문에 중요도를 먼저 본다.

## 하지 않는 것

- 사진·문자로 넣는 일정(`extract-entries`의 event 경로, `eventCheck.ts`, `EventCaptureSheet`)의 끝 날짜·중요도 읽기: 기본값(하루·보통)으로 들어가고, 넣은 뒤 고치기에서 정한다. 서버 함수는 바뀌지 않는다.
- 캡처 확인 화면의 "이미 있는 일정" 견주기에 기간 넣기(같은 날·같은 이름 기준 그대로).
- 기념일(반복)의 중요도·효과, 일정 반복, 끝 시간, 알림(푸시).
- 중요도별 거르기·모아 보기.

## 운영 반영

1. 공유 DB에 `20261115000000_event_range_priority.sql` 적용(Supabase MCP `apply_migration`, 사용자 승인 뒤). **화면보다 먼저**: 새 화면은 일정을 읽을 때 `end_on`·`priority`·`effect`를 함께 고르므로, 칸이 없으면 일정이 달력에 보이지 않는다(가계부 내역은 그대로).
2. main 병합·푸시(Pages 배포). 서버 함수 변경 없음.
3. 이 버전 전의 앱(캐시된 PWA)은 새 칸을 보내지 않아 기본값으로 넣고, 고칠 때는 새 칸을 건드리지 않는다.
