# 상품명 → 식약처 품목 맞춤 다시 만들기 (원재료·영양성분)

날짜: 2026-10-23 · 브랜치 `claude/product-match` · 결정 기록 D-026(이 문서로 정함)

## 1. 왜

사용자(2026-10-23): "상품명의 성분 매칭은 아직 매우 부족해."

운영 DB(가구 품목 21개, 상품을 고른 것 15개)를 보면 다음과 같다.

- 원재료: 자동 맞춤으로 저장된 줄이 0건이다. v9 배포 뒤 성분 탭을 연 품목은 굴소스 하나였고 `no_fit`이었다.
- 영양성분: 고추장은 다른 회사 제품("순창 아주존 태양초 찰고추장 골드", 주식회사순창우리식품)이 상품명 맞춤으로 저장돼 있다. 미림은 "미림 구운계란"(미림유통)이 이름 맞춤으로, 된장은 v6 이전에 맞춘 "취나물_된장"이 그대로 남아 있다.
- 지난 다섯 번의 고침(D-018 보충 1~3, D-020 보충 1~2)은 모두 "신고된 사례 하나에 규칙 하나"였다. 정답표가 없어서 한 품목을 고치면서 다른 품목이 틀려져도 보이지 않았다.

원인은 다섯 가지다(2026-10-23 sample 키 실제 호출, 다나와 상품 페이지 15개 실제 읽기).

1. **상표와 업체명이 다르다.** 청정원 제품의 업체는 대상(주), 큐원 제품은 (주)삼양사, 롯데푸드 미림은 롯데칠성음료(주)다. 상표로 업체명(`BSSH_NM`)을 걸면 0건이 나와 정답 후보가 들어오지 않는다. 다나와 상품 페이지의 `makerName`에는 대상·삼양사가 그대로 적혀 있다.
2. **업체가 달라도 낱말 2개가 겹치면 맞다고 본다**(`productFit`). 그래서 다른 회사 찰고추장이 붙었다. 낱말 1개와 업체가 맞아도 통과하므로 "오뚜기 진라면 순한맛"에 "그대로카레순한맛"이 붙을 수 있다.
3. **상품을 골랐는데 상품명 맞춤이 실패하면 품목 이름 맞춤으로 넘어가면서 상용제품까지 받아들인다.** 그래서 "미림 구운계란"이 붙었다.
4. **수입품은 품목제조보고에 업체가 없다.** 이금기(다나와 원산지 홍콩산), 폰테라 앵커가 그렇다. 화면은 이유 없이 "찾지 못했어요"만 낸다.
5. **한 번 자동으로 맞춘 줄은 로직이 바뀌어도 다시 맞추지 않는다.** 고쳐서 배포해도 화면이 그대로다.

덤으로 느리다. 단계마다 차례로 불러 한 번 열 때 최대 17번을 부르고, 12.5초 걸린 적도 503이 난 적도 있다(2026-10-22 02:30 UTC 로그).

## 3. 확인한 사실 (2026-10-23)

식약처 `sample` 키 실제 호출. sample 키는 범위와 상관없이 앞 5줄만 준다. `6/10`을 요청해도 `1/5`와 같은 줄이 온다.
- `PRDLST_NM`은 띄어쓰기까지 그대로 대조하는 부분 일치다. 예를 들어 업체를 대상으로 걸면 "양념 듬뿍"은 0건이고 "양념듬뿍"은 "청정원순창양념듬뿍쌈장"을 찾는다. 낱말 하나("찰고추장")로 찾으면 띄어 쓴 이름과 붙여 쓴 이름이 둘 다 걸린다.
- `%`가 든 검색어에는 `Not Acceptable`(HTML)이 돌아온다.
- 업체명 조건은 부분 일치라 "대상"에 "현대상회"·"대상웰라이프"가 같이 걸린다.
- 이름이 거의 같은 두 품목의 원재료가 다르다.
  - 19850499011151 "청정원순창태양초찰고추장": 고추양념, 현미, 찰현미…
  - 1985049901172 "청정원 순창 태양초 찰고추장": 찹쌀, 밀가루…
  - 다나와 원산지 표기("고추양념(중국산), 현미(외국산)")와 맞는 것은 앞의 것이다.

## 5. 정한 것

### 5-1. 다나와 상품 정보 저장

- `parseDanawaProduct`가 `makerName`·`brandName`·원산지(설명 메타 `원산지: …`의 `/` 앞까지)도 읽는다. 없으면 null이다.
- 마이그레이션 `20261103000000_grocery_product_facts.sql`(`grocery` 스키마만): `grocery.products`에 `maker`(≤60), `brand`(≤60), `origin`(≤200), `materials`(≤200, 설명의 "원재료명: …"), `facts_at timestamptz`를 더한다.
- 쓰는 곳은 세 군데다.
  - `product-check`·`price-recheck`의 저장: 페이지를 읽을 때 같이 쓴다. 읽은 값(null 아닌 칸)만 덮는다(페이지 모양이 바뀌어도 있던 제조사를 지우지 않게).
  - `food-info`: `facts_at`이 없으면 상품 페이지를 한 번 읽어 쓴다.
  - 모두 서비스 롤로 쓴다.

### 5-2. 맞춤 한 번으로 원재료·영양성분 (`_shared/productMatch.ts`, 순수 함수)

**낱말 나누기**
- 상품명 낱말(`productWords`)을 세 가지로 나눈다.
  - 상표 낱말: 첫 낱말, 다나와 brand 낱말, maker
  - 찾을 낱말: 나머지에서 숫자·`%`가 든 말을 뺀 것. 뒤에서부터 3개(상품 핵심어가 뒤에 온다)
  - 설명 낱말: 전부. 커버리지를 셀 때 쓴다
- 업체 열쇠: maker. 3자 이상이면 앞 2자도("롯데푸드" → "롯데"는 롯데칠성음료를 잡는다). maker가 없으면 지금처럼 첫 낱말을 쓴다.

**찾기**
- 한 번에 부른다: 업체 열쇠 첫째 × 찾을 낱말 × 세 목록(C002·I1310·C003), 업체명+이름 조건.
- 업체+이름 호출은 100줄을 받고, 응답의 `total_count`가 더 많으면 300번째 줄까지 한 쪽 더 받는다(결과가 이름 순이라 "청정원…"(ㅊ)이 뒤에 온다; 정답표 시험의 가짜 API는 모은 줄만 있어 창이 넘치는 경우를 보지 못한다).
- 모두 0건이면 앞 2자 열쇠로 한 번 더.
- 그래도 0건이면 더 부르지 않는다(`maker_missing`). 낱말만으로 찾으면 다른 회사 제품뿐이라 화면에 낼 것이 없고 호출만 는다(빌더 검토 반영, 내가 정함). 다나와 제조사를 모르는 상품만 지금처럼 상표(첫 낱말) 열쇠 뒤에 낱말 100건을 후보로 부른다.
- **처음 맞는 단계에서 멈추지 않고 모은 다음 고른다.**

**점수**
- 업체 일치: 후보 업체명에서 법인 표기("(주)"·"㈜"·"주식회사")를 뺀 뒤 업체 열쇠로 시작하는가. "현대상회"는 "대상"으로 시작하지 않는다. 첫째 열쇠(제조사 그대로)로 맞았는지(`makerFull`)도 따로 준다: 앞 2자 "롯데"는 롯데칠성음료도 롯데리아도 맞는다.
- 후보 쪽 커버리지(`cover`): 후보 이름(기호 뺌)의 글자 가운데 설명 낱말로 설명되는 비율.
  - "청정원순창태양초찰고추장" 1.0
  - "청정원 순창 태양초 찰고추장 골드" 0.86
  - "수출올리브짜파게티과립스프(NSA)" 약 0.4
- 상품 쪽 일치(`recall`): 찾을 낱말과 숫자 낱말("1%"는 "1")이 후보 이름에 든 비율.
- 원산지 대조(`originHits`): 다나와 원산지에 적힌 원재료 이름("고추양념", "현미")이 후보 원재료(`RAWMTRL_NM`)에 든 수. 원재료가 없는 줄(I1310)은 0으로 둔다.
- 순서: 업체 일치 → `cover` → `recall` → `originHits` → 변경일(`CHNG_DT`)이 늦은 것 → 짧은 이름.

**자동 저장 기준**
- 업체 일치, `cover ≥ 0.8`, `recall ≥ 0.5`일 때만 저장한다(`shouldAutoSave`).
- 아니면 저장하지 않고 앞 3개를 "같은 상품인지 확인해 주세요" 후보로 돌려준다.

**저장할 것**
- 원재료: 고른 줄. I1310이면 지금처럼 C006에서 보고번호로 받는다.
- 영양성분: 식품영양성분DB를 같은 보고번호(`ITEM_REPORT_NO`)로 부른다(`matchedBy: 'report'`). 없으면 상품명 영양 검색 결과에도 같은 업체 일치·`cover` 기준을 건다(`MAKER_NM`). 그래도 없으면 품목 이름의 **품목대표만**(음식 제외) 쓴다(`matchedBy: 'name'`). 상용제품 이름 맞춤은 상품이 있는 품목에서는 쓰지 않는다.

### 5-3. 새 액션 `product_auto`

- 상품을 고른 품목에서 성분 탭을 열면 화면이 이것 하나만 부른다. 원재료와 영양성분을 함께 맞춰 저장한다.
- 돌려주는 것: `{ ingredients, nutrition, reason, candidates, maker, origin }`
- `reason`의 값
  - `maker_missing`: 업체 열쇠로 세 목록 모두 0건
  - `unsure`: 후보는 있지만 기준 미달
  - `no_rows`: 아무 결과 없음
  - `failed`: 목록 오류. 실패한 목록 이름을 함께 준다
- 예전 `ingredients_auto`·`nutrition_auto`는 남긴다. 캐시된 옛 화면이 부를 수 있다. 상품이 있으면 안에서 같은 맞춤을 쓴다.

### 5-4. 다시 맞추기(버전)

- 자동 맞춤 줄에 `v: 2`를 남긴다. 영양은 nutrition jsonb, 원재료는 details에 둔다.
- 화면은 저장된 줄이 `auto`이고 `v`가 2보다 작으면 탭을 열 때 `product_auto`를 다시 부른다.
- 다시 맞춘 결과가 없으면 옛 자동 줄을 지운다. 새 SQL 함수 `grocery.clear_item_auto(p_item, p_version)`(서비스 롤)을 쓴다. 목록 호출이 모두 실패하면 지우지 않는다.
- 저장 함수(`set_item_nutrition`·`set_item_ingredients`)는 들어오는 줄이 자동이고 있는 줄이 자동이 아니면 덮지 않는다(같은 마이그레이션, `create or replace`). 화면이 원재료는 사람이 고르고 영양은 옛 자동인 품목에서 `product_auto`를 불러도 사람이 고른 원재료가 남는다.
- 못 맞춘 결과는 기억하지 않는다. 탭을 열 때마다 다시 찾는다(지금과 같다, 두 사람이 쓰는 앱이라 호출이 적다; 내가 정함).
  - `chosen_by`가 null이고 auto이며 v가 p_version보다 작은 줄만 지운다.
  - 같은 마이그레이션에 넣는다.
- 사람이 고른 줄(우유 "우유", 쌈장 "청정원 순창 진쌈장", 삼겹살)은 그대로 둔다.

### 5-5. 화면 (성분 탭)

- `maker_missing`: "식약처 품목제조보고에 '이금기' 이름으로 보고된 품목이 없어요. 다른 회사가 만들었거나 수입 제품일 수 있어요(다나와 원산지: 홍콩산)." 그리고 "식약처 품목 찾기". 원산지가 없으면 괄호를 뺀다.
- `unsure`: "같은 상품인지 확인해 주세요". 후보 3개(이름 · 업체 · 식품유형 · 보고번호)마다 "이 상품이에요" 버튼을 둔다. 고르면 `ingredients_choose`이고, 영양도 그 보고번호로 맞춘다.
- 진행 문구: "식약처 품목제조보고에서 상품 찾는 중". "AI"·"분석" 같은 말은 쓰지 않는다.
- 영양 출처 줄: `matchedBy: 'report'`면 "보고번호로 자동 맞춤", 품목대표 대체면 "품목 이름으로 자동 맞춤(일반 식품)".

### 5-6. 정답표 시험

- 사본: `tests/grocery/fixtures/foodsafety/match-rows.json`. 2026-10-23 sample 키 응답에서 모은 실제 줄(보고번호·이름·업체·식품유형·원재료·변경일)이다. 시험의 가짜 API가 주소의 조건(`BSSH_NM`·`PRDLST_NM`·`PRDLST_DCNM` 부분 일치, 띄어쓰기 그대로)과 범위로 이 줄을 이름 순으로 걸러 준다. 다나와 사실은 시험 안 표(3절)로 둔다.
- `tests/grocery/productMatch.golden.test.ts`: 4절 표를 그대로 단언한다. 틀린 자동 저장 0건, 정답 11개 자동.
- 운영 키 평가(선택): `scripts/match-eval.mjs`가 `~/.config/acout-book/food-keys.env`(저장소 밖)를 읽어 15개를 실제로 돌리고 표만 출력한다. 키를 출력하거나 저장하지 않는다. 사용자가 키 파일을 넣었을 때만 돈다.
- 영양성분은 정답표가 없다(공공데이터포털에 sample 키가 없다). 보고번호(`ITEM_REPORT_NO`) 경로가 운영에서 되는지는 확인 필요이고, 안 되면 업체 일치 기준을 건 상품명 검색으로 넘어간다. 영양의 완료 기준은 "다른 업체 상용제품을 자동 저장하지 않는다"(시험으로 단언)이다.
- 배포 전에 운영 키 평가를 할지는 배포를 여쭐 때 함께 묻는다(빌더 검토 1번, 사용자가 정함).
