# 알아보기 탭: 가격 비교와 날씨·미세먼지 (D-035)

2026-10-28 사용자 요청: k-skill을 넣은 뒤 "추가한 기능이 많은데 새롭게 탭을 추가하던가 해". 고르기에서 "앱에서 직접 조회"와 먼저 넣을 것 "가격 비교, 날씨·미세먼지"를 골랐다.

## 왜

k-skill 스킬은 컴퓨터의 Claude Code 대화에서만 쓰는 조회 도구라 폰의 가계부에는 아무것도 생기지 않았다. 두 사람이 폰에서 바로 쓰려면 앱 화면과 서버 함수가 따로 있어야 한다. 스킬의 값이나 k-skill 프록시는 앱에 쓰지 않는다(D-034: 얻은 숫자를 앱 화면·DB에 넣지 않는다).

## 하는 것

1. **아래 탭 하나 더: "알아보기"**(돋보기 아이콘). 달력·내역·장보기·통계·고정 다음 여섯째. 휴대폰 아래 탭은 6칸(한 칸 약 65px), 넓은 화면 왼쪽 메뉴는 여섯 줄 + 설정. 아래 탭을 3~5개로 둔 D-010은 사용자 요청으로 6개로 고친다.
2. **날씨·미세먼지 묶음**(탭 맨 위)
   - 위치: 기기마다 고른다. 기본은 성남시청 근처(37.42, 127.13). "현재 위치로"를 누르면 기기 위치를 소수 둘째 자리(약 1km)로 줄여 서버에 보낸다. "성남으로" 버튼으로 돌아간다. 고른 위치는 그 기기에만 저장한다(`localPrefs`).
   - 지금: 기온, 비·눈 여부(강수형태), 1시간 강수량, 습도. 출처 줄 "기상청 초단기실황 HH:00 관측".
   - 오늘·내일: 최저·최고 기온, 하늘(맑음·구름많음·흐림), 하루 중 가장 높은 강수확률. 출처 줄 "기상청 단기예보 MM월 DD일 02:00 발표".
   - 미세먼지·초미세먼지: 농도(㎍/㎥)와 에어코리아가 준 등급(좋음·보통·나쁨·매우나쁨). 등급이 없으면 "등급 없음"(앱이 농도로 등급을 만들지 않는다). 출처 줄 "에어코리아 ○○ 측정소, HH시". 위치 이름은 따로 찾지 않고 가장 가까운 측정소 이름과 주소로 보인다.
   - 진행·실패 문구: "기상청 예보 받는 중", "날씨를 받지 못했어요(기상청 응답 없음)", 활용신청 전에는 "기상청 예보는 공공데이터포털 활용신청 뒤에 보여요". 날씨와 미세먼지는 따로 실패할 수 있다.
3. **가격 비교 묶음**
   - 검색 칸(예: 비비고 왕교자 1.05kg) → 다나와 검색 결과 상품 줄: 이름, 수량별 최저가(1개·2개…), 100g당 같은 단위 가격, 판매처 수, 평점(후기 수). 머리에 "다나와 검색, 오늘 11:40 확인".
   - 상품을 누르면 시트: 다나와 상품 페이지의 쇼핑몰별 최저가(몰·상품가·배송비·합계, "N개 묶음 기준"), 수량별 최저가, 평점, "다나와 상품 페이지, 오늘 11:41 확인", 다나와에서 보기 링크.
   - 진행 문구: "다나와 순서 기다리는 중(10초에 한 번)", "다나와 검색 중". 바쁘면 "다나와 검색이 밀려 있어요. 잠시 뒤 다시 찾아 주세요".

## 하지 않는 것

- 네이버 쇼핑: 공식 API가 2026-07-31 종료됐고 쇼핑 검색 페이지는 robots가 막는다(`docs/grocery/data-sources.md` 1-1).
- 컬리·쿠팡·다이소 등 몰 검색, 번개장터·당근: robots·브라우저 필요·제3자 서버라 앱에 넣지 않는다.
- 검색한 상품을 장보기 목록에 담기, 지역 이름 검색·주소 입력, 주간 예보, 알림.
- 날씨 값 DB 저장.

## 정한 방식

- **서버 함수 둘**(둘 다 `verify_jwt = true`, 키는 `DATA_GO_KR_SERVICE_KEY` 하나, 커밋 고정 stub 배포 D-023 보충).
  - `explore-weather`: `POST {lat, lng}`. 소수 둘째 자리로 자르고 한국 범위(위도 32.5~39, 경도 124~132.5) 밖이면 400. 기상청 격자(nx, ny)는 기상청 람베르트 변환 공식, 초단기실황은 지금에서 40분 뺀 시각의 정시, 단기예보는 오늘 02:00 발표(02:10 전이면 어제 23:00 발표)를 받아 오늘·내일 최저·최고·하늘·강수확률을 만든다. 에어코리아는 WGS84 → TM 변환(`fine-dust-location` 스킬의 MIT 코드를 옮김) → 근접측정소 목록의 첫 측정소 → 측정소별 실시간 측정(ver 1.3). 응답은 `{weather, air}`이고 각각 값 또는 `{status: 'not_registered' | 'error'}`. DB 캐시는 두지 않는다(두 사람 호출량은 공공데이터포털 하루 한도보다 훨씬 작다). 앱이 같은 위치 결과를 기기에 10분 둔다.
  - `explore-price`: `POST {query}` 또는 `POST {pcode, name}`.
    - 검색: 공백 정리 2~60자. 한국 날짜가 같고 정규화한 검색어가 같으면 `grocery.explore_searches`의 결과를 돌려준다(같은 출처·같은 날 캐시 규칙). 없으면 `grocery.reserve_fetch('danawa-search', 10000, 30000)`로 장보기와 같은 전역 10초 자리를 잡는다(30초 넘게 밀리면 202 busy). 파서는 `_shared/danawa.ts` 그대로.
    - 상품: pcode는 숫자 4~12자리. `grocery.products`에 (danawa, pcode)가 없으면 검색 결과 이름으로 넣는다. 오늘 성공한 `price_checks`가 있으면 그것을, 없으면 `_shared/priceCheck.ts`의 `checkDanawa`로 상품 페이지를 읽어 장보기와 같은 `price_checks`·`price_quotes`에 저장한다. 저장 코드는 `product-check`와 같은 것을 `_shared/priceStore.ts`로 옮겨 쓴다. 응답은 가장 최근 성공 확인의 가격 줄.
  - 권한: 로그인한 사람이면 부를 수 있다(가구 데이터를 읽거나 쓰지 않는다). 가구 내역·품목은 보내지 않는다.
- **DB**: 장보기 스키마에 `grocery.explore_searches(query_key, searched_on, query, items jsonb, found_at)` 하나(기본 키 query_key + searched_on). RLS 켜고 정책 없음, 서비스 롤만 읽고 쓴다. 30일 지난 줄은 새 검색을 넣을 때 지운다. 마이그레이션은 grocery 스키마만 바꾼다(D-003).
- **화면**: `src/components/ExploreView.tsx`(늦게 불러오기, 장보기처럼 `prefetchChunks`), 호출·위치·글자 만들기는 `src/lib/explore.ts`, 가계부 `styles.css`의 `.explore` 아래 규칙(앱에 이미 다른 뜻의 `src/lib/lookup.ts`가 있어 이 기능의 코드 이름은 explore로 통일). 숫자는 모두 출처·기준 시각과 함께 쓴다. "AI"·반짝이·"분석 중" 같은 말은 쓰지 않는다.
- **버전**: v2.12.0(기능 추가).
- **운영 반영 순서**(사용자 확인 뒤): ① 사용자가 공공데이터포털에서 같은 계정으로 활용신청 3개(기상청 단기예보 15084084, 에어코리아 대기오염정보 15073861, 에어코리아 측정소정보 15073877) ② MCP `apply_migration` ③ 함수 2개 배포 ④ main 병합. 화면이 먼저 나가도 함수가 없거나 활용신청 전이면 실패 문구만 보인다.
