# 함께 살 물건 보관함과 전체 조회 보완

## 요청

부부가 함께 살지 고민하는 물건을 보관한다. 기존 추천 중 보관함만 추가한다.
CSV와 기간 조회의 행 제한에 따른 누락도 고친다. 입력 임시저장과 품목 편집은 이번 범위가 아니다.

## 보관함 제안

- 사용자가 고른 배치: 기존 ‘장보기’의 ‘목록 / 시세’ 옆에 ‘보관함’을 둔다. 아래 탭은 늘리지 않고 당장 살 목록과도 섞지 않는다.
- 부부가 같은 목록을 보고 추가·수정·삭제·샀어요 표시를 한다. ‘샀어요’는 다시 되돌릴 수 있다.
- 이름(필수), 상품 링크, 목표 가격, 메모를 넣는다. 목표 가격은 사용자가 정하는 값임을 표시한다.
- 가격 검색 결과에서 ‘보관하기’를 누르면 그 상품 이름·링크와 확인한 가격·출처·시각을 함께 가져온다.
- 보관한 가격은 ‘보관할 때 확인한 가격’이다. 최신 가격으로 표현하거나 자동으로 갱신하지 않는다.
- 보관함에서도 직접 물건을 넣을 수 있다. 저장한 이름으로 기존 가격 검색을 다시 열 수 있다.
- 가구별 DB 저장과 RLS로 다른 가구에서는 접근하지 못하게 하고, 변경 알림·앱 복귀 때 목록을 새로 읽는다.
- 샀다고 표시해도 가계부 지출은 자동 생성하지 않는다. 가계부의 영수증·직접 입력 흐름을 그대로 쓴다.
- 가구 공동 목록에서 보관 중인 물건과 산 물건을 나눠 본다. 작성자를 표시하고 별도 의견 투표나 채팅은 넣지 않는다.

## 접근 방식과 선택

1. 알아보기 안의 보관함: 가격 검색 결과와 가깝지만 사용자는 장보기 배치를 선택했다.
2. **장보기 안의 별도 보관함(사용자 선택)**: 구매할 물건을 장보기에서 함께 관리하면서 기존 목록의 체크·가격 합계와는 분리한다.
3. 새 아래 탭: 진입은 빠르지만 현재 여섯 탭을 더 늘린다.

사용자가 설계 확인 질문에서 2번(‘장보기 안에 보관함 배치’)을 선택했다. 그 밖의 제안 범위를 유지해 구현한다.

## 데이터와 실패 처리

- `grocery.purchase_wishes`: 가구, 이름, 링크, 목표 가격, 메모, 출처 가격·확인 시각·수량 설명, 구입 시각, 작성자·수정 시각.
- 외부 링크는 HTTP(S)만 허용한다. 가격의 0원·음수·범위 초과 입력을 막는다. 가격을 모르면 빈 값이다.
- 가격 검색의 링크는 결과에 있던 주소만 쓴다. 수량·배송비 포함 여부를 함께 보관해 가격 의미를 보존한다.
- 저장 실패 시 입력을 유지하고 오류를 표시한다. 목록을 못 불러오면 빈 보관함으로 오인하지 않게 재시도를 제공한다.
- 공유 DB 적용은 CLAUDE.md에 따라 사용자가 구체적인 마이그레이션을 확인한 뒤에만 한다.
- 같은 링크를 다시 보관하면 기존 항목을 편집한다. 링크가 없는 같은 이름의 물건은 임의로 합치지 않는다.
- 상품 링크를 바꾸면 이전 상품의 가격 기록은 비운다. 화면과 DB 트리거에서 모두 처리한다.

## CSV·조회 보완

- CSV 다운로드, 두 달 내역, 기간 내역은 페이지를 끝까지 읽고 날짜·생성 시각·ID로 안정적으로 정렬한다.
- 서버 행 제한이 페이지 크기보다 작아도 조기 종료하지 않도록 전체 개수를 함께 확인한다.
- 중간 조회 실패를 일부 내역 다운로드 성공으로 처리하지 않는다.
- 구글 시트 내보내기 함수의 정렬에도 ID를 추가한다. 페이지별 전체 개수 확인으로 제한에 따른 조기 종료를 막는다.
- 기존 ‘최근 1,000건’처럼 의도적으로 제한한 과거 품목 비교 범위는 유지한다.
- 행 제한에 따른 누락을 해결하는 범위다. 여러 HTTP 요청 중 생긴 모든 동시 삽입·삭제의 일관된 스냅샷까지 보장하지 않는다.

## 검증

- 1,000건 초과, 작은 서버 행 제한, 같은 날짜·생성 시각, 빈 결과, 중간 페이지 실패를 검증한다.
- 보관함은 부부 공유·다른 가구 차단·미로그인 차단·입력 검증·수정·구입 상태를 검증한다.
- 전체 테스트·타입 검사·린트·빌드와 390·1280px, 라이트·다크 화면을 확인한다.
