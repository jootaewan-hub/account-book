## 1. 왜

D-008(2026-10-19): 가계부 앱을 메인으로 두고 그 안에 장보기 탭을 만든다. 두 앱은 이미 같은 Supabase 프로젝트(ref `kifdfpbwiebfgvdumqjf`), 같은 계정·가구(`public.households`, `public.members`)를 쓰고(D-003, D-004), 디자인 체계도 같다(D-005). 지금은 두 사람이 앱 두 개를 따로 설치해 쓰고, 장 본 금액과 가계부 내역이 이어지지 않는다.

### 목표

- 가계부 앱 하나에서 장보기 목록·담기·후보 고르기·품목 상세·식약처 경고를 지금과 똑같이 쓴다.
- 장보기 코드·마이그레이션·Edge Function·예약 실행을 가계부 저장소 하나에서 관리하고, 배포도 하나로 한다.
- 장 본 것이 가계부 내역이 되고, 가계부의 구매 기록이 장보기 가격 비교의 "우리가 산 값"이 된다.

### 비목표 (이번 설계에서 다루지 않음)

- 장보기의 남은 계획 자체(④ 나머지 출처·사진·캡처, ③ KAMIS 시세, 바코드). 통합 뒤 가계부 저장소에서 이어 한다. 이 문서는 그 화면이 들어갈 자리만 정한다.
- 가계부 기존 화면(달력·내역·통계·고정)의 동작 변경. 바뀌는 것은 설정으로 가는 길(3-1)뿐이다.

### 실패 조건 (동작해도 실패로 본다)

- 옮긴 뒤 장보기 화면이 옮기기 전과 다르게 동작하거나 보인다(의도한 변경인 탭·설정 위치 제외).
- 장보기 CSS가 가계부 화면을, 또는 가계부 CSS가 장보기 화면을 바꾼다(3절 클래스 이름 충돌).
- 장보기 규칙(4-4절)이 통합 뒤 장보기 부분에서 하나라도 깨진다. 특히 출처 없는 숫자, "기록 없음"을 "안전함"으로 쓰기.
- 같은 지출이 가계부에 두 번 들어가는 경로가 확인 없이 열린다(6-1절).
- 옮기는 도중 공유 DB의 스키마나 데이터가 바뀐다. 1단계(7절)는 DB를 건드리지 않는다.

## 3. 화면

### 3-1. 탭 구성 [사용자]

휴대폰 아래 탭은 5개로 둔다. Apple HIG와 Material 모두 아래 탭을 3~5개로 권한다.

```
┌──────────────────────────────┐
│ 우리집            ‹ 10월 › ⚙ │
│   (화면)                      │
├──────────────────────────────┤
│ 달력  내역  장보기  통계  고정 │
└──────────────────────────────┘
```

- **설정**은 탭에서 빼고 화면 위 오른쪽 톱니 버튼(`aria-label="설정"`, 44px 터치 대상)으로 연다. 모든 탭의 위쪽 줄에 있다. 누르면 지금의 설정 화면(설정 + 내보내기)이 열린다. 열리는 방식(탭 화면 바꾸기 / 전체 화면 시트)은 [빌더]다. 단 지금 설정 화면의 길이와 내보내기 카드를 생각하면 화면 바꾸기와 "‹ 돌아가기"가 자연스럽다.
- 넓은 화면(960px 이상)의 왼쪽 세로 메뉴에는 공간이 있으므로 5개 탭 아래에 "설정"을 한 줄 더 두고, 위쪽 톱니 버튼은 넓은 화면에서 숨긴다 [제안]. 휴대폰과 다르게 하고 싶지 않으면 넓은 화면도 톱니 버튼만 둔다.
- 탭 아이콘: 장보기는 `Icons.tsx`의 24 격자·선 1.75px 규칙으로 새로 그린다(장바구니) [빌더]. 이모지는 쓰지 않는다(가계부 DESIGN.md).
- 아래 탭 전환에는 움직임이 없다(가계부 Motion 규칙).

### 3-2. 장보기 탭 안

- 위쪽 줄: 제목 "장보기"와 톱니 버튼. 달 이동(‹ 10월 ›)은 없다. 장보기 목록은 달 단위가 아니다.
- 본문: 지금 장보기 `ListScreen` 그대로. 요약 세 칸(살 것, 찾은 최저가 합계, 확인 못 함), 보기 전환(분류별 | 어디서 살지), 식약처 확인 상태 줄, 분류 묶음.
  - 장보기 `ListScreen`에는 자체 제목 머리(`list-head`, "로그아웃" 버튼 포함)가 있다. 통합 뒤 제목은 가계부 위쪽 줄이 맡고 로그아웃은 설정에만 둔다 [제안].
  - 장보기 로그아웃은 기다리던 빼기(되돌리기 알림 동안 미뤄 둔 삭제)를 서버에 보낸 뒤에 세션을 끝낸다(`ListScreen.tsx`의 `signOut`). 그렇지 않으면 삭제 요청이 거부된다. 로그아웃이 가계부 설정으로 가도 이 순서를 지킨다. 장보기 탭이 그 함수를 앱에 등록해 두고 설정의 로그아웃이 먼저 부르는 식이다 [빌더].
- 주 행동: 휴대폰은 지금처럼 화면 아래 "담기" 큰 버튼(`bottom-bar`). 가계부의 둥근 "기록하기" 버튼(`fab`)은 지금도 달력·내역 탭에서만 보이므로 장보기 탭과 겹치지 않는다.
- 넓은 화면: 왼쪽 메뉴 맨 위 "기록하기"는 그대로 두고(가계부 내역 입력), 장보기 탭의 "담기"는 목록 머리 오른쪽에 둔다(지금 장보기의 `only-wide` 배치).
- 시세 화면(계획 ③)이 생기면 장보기 탭 안에 "목록 | 시세" 전환을 둔다 [제안]. 아래 탭은 늘리지 않는다.
- 다른 곳에서 장보기 탭을 바로 여는 주소: `https://jootaewan-hub.github.io/account-book/?tab=grocery`. 예전 장보기 주소의 안내 페이지(7절 3단계)가 이 주소로 보낸다. 앱 안에서 탭을 바꿀 때 주소창을 바꿀지는 [빌더].

### 4-3. CSS: 이름 충돌과 토큰

**겹치는 클래스 10개**(2026-10-19 두 CSS에서 셈): `.seg` `.sheet` `.sheet-head` `.summary` `.tag` `.check` `.empty` `.who` `.who-husband` `.who-wife`. 그대로 합치면 서로의 화면이 깨진다.

- `grocery.css`의 모든 선택자를 `.grocery` 아래로 둔다(예: `.grocery .seg`). 장보기 화면의 바깥 상자에 `className="grocery"`를 단다.
- 반대 방향(가계부 `.seg` 등이 장보기 안으로 새는 것)도 막아야 한다. 가계부 `styles.css`의 겹치는 10개 선택자에 `:where(:not(.grocery *))`를 붙이는 방법과, 장보기 쪽에서 해당 속성을 모두 다시 정하는 방법이 있다. 어느 쪽이든 겹치는 10개 클래스로 화면 캡처 비교를 해서 확인한다 [빌더].
- 장보기의 전역 규칙(`*`, `html`, `body`, `button` 등 `tokens.css` 아래쪽)은 가계부에 이미 같은 뜻의 규칙이 있어 버린다. 다른 것: 장보기 `body`는 16px, 가계부 `body`는 15px. 장보기 화면은 `.grocery { font-size: 16px }`로 지금 크기를 지킨다.

**CSS 변수**: 장보기 이름을 가계부 이름으로 바꾼다. 라이트·다크 값은 같다(아래 한 곳만 다름).

| 장보기 | 가계부 | 비고 |

## 6. 두 앱이 만나는 기능

통합 1단계(7절)가 끝난 뒤의 별도 계획이다. 여기서는 방식만 정한다.

### 6-1. 장 본 것 → 가계부 내역 [사용자: 두 길 다]

지금 사실: `grocery.items`에 `paid`(낸 금액)·`bought_at`·`bought_by` 칸이 있지만 금액을 넣는 화면은 없다(목록 줄이 `paid`를 보여 주기만 한다). 가계부는 영수증·주문 캡처를 품목까지 읽어 상품별 내역으로 나눠 저장한다(`add_transaction_with_items`).

**연결 표시** [제안]: 장보기 품목이 어느 가계부 내역이 됐는지 `grocery` 스키마에 남긴다(예: `grocery.items.transaction_id uuid references public.transactions(id) on delete set null`). D-003·D-007처럼 장보기 쪽 칸이 가계부를 참조만 하고, 가계부에서 내역을 지우면 연결만 풀린다. 연결된 품목은 두 길 어디에서도 다시 넣지 않는다. 이 규칙이 같은 지출을 두 번 넣지 않게 막는다. 열 이름·품목 단위(`transaction_items`)까지 연결할지는 [빌더].

**길 ① 영수증이 있을 때: 가계부 스마트 입력에서**

1. 지금처럼 기록하기 → 사진(영수증·주문 캡처) → 확인 화면.
2. 확인 화면 아래에 "장보기 목록에서 찾은 품목" 묶음을 둔다. 대상은 가구의 장보기 품목 중 아직 가계부와 연결되지 않은 것이다(안 산 것 + 산 것). 영수증 상품명과 이름이 맞는 것을 미리 체크해 보여 준다. 맞추는 규칙은 [빌더]다. 장보기 `categorize`와 같은 사전·단어 일치를 쓰면 된다.
3. 저장하면 체크한 장보기 품목은 산 것(`bought_at` = 내역 날짜, `bought_by` = 저장한 사람), `paid` = 그 영수증 상품 금액(출처: 영수증)이 되고, 만들어진 내역과 연결된다.
4. 장보기 품목과 맞는 게 없으면 묶음을 보여 주지 않는다. 확인 화면의 다른 부분은 바뀌지 않는다.

**길 ② 영수증이 없을 때(현금·시장): 장보기에서 "가계부에 넣기"**

1. 장보기 목록에 산 품목 중 연결 안 된 것이 있으면 "가계부에 넣기" 버튼을 둔다(산 품목 묶음 아래).
2. 시트: 넣을 품목 체크(기본: 오늘 산 것 전부), 날짜(산 날), 어디서(가게 이름, 가계부 `PlatformInput`), 누구(기본 공동), 금액.
   - 금액은 사용자가 적은 값만 쓴다. 다나와 최저가 같은 확인한 가격을 낸 금액으로 미리 채우지 않는다. 출처가 다른 값이다.
   - 총액 하나만 적어도 되고 품목마다 적어도 된다.
3. 저장 방식은 가계부 규칙을 따른다. 품목마다 금액이 있으면 상품별 내역으로 나누고, 총액만 있으면 한 내역(품목 목록은 `transaction_items`로)으로 넣는다. 분류는 6-3절이다.
4. 쓰기는 가계부의 기존 함수 `public.add_transaction_with_items`로 한다. 장보기 쪽 연결 표시까지 한 번에 묶을 함수가 필요하면 `grocery` 스키마에 하나 만들어 그 안에서 가계부 함수를 부른다. "가계부 내역에 쓰는 것은 함수 하나로"(장보기 architecture.md)를 지킨다 [제안].
5. 저장 버튼 이름은 결과를 말한다("3개 23,400원 가계부에 넣기").

**중복 안내**: 연결 표시로 막지 못하는 경우가 남는다. 길 ②로 넣은 뒤 같은 장의 영수증을 연결 없이 스마트 입력으로 또 넣는 경우다. 이때는 스마트 입력의 기존 중복 경고(`src/lib/smart.ts`의 "같은 날 같은 금액 내역이 이미 있어요")가 알린다. 단 날짜와 금액이 같을 때만 알린다. 길 ②에서 총액 한 건으로 넣고 영수증을 상품별로 나누면 금액이 달라 경고가 뜨지 않을 수 있다. 그래서 길 ①의 "장보기 목록에서 찾은 품목" 묶음에 "이미 가계부에 넣은 품목"(연결된 것)도 흐리게 보여 주고 "이 장보기는 이미 넣었어요"라고 적는다 [제안].

### 6-2. 가계부 기록 → "우리가 산 값" [사용자: 연결 기록 + 이름 비슷한 기록]

- 품목 상세 가격 탭의 비교 줄에 둔다. 화면 설계 4절대로 태그는 "우리가 산 값"(`blush-soft` 바탕, `rose-ink` 글자)이다. 과거 값이라 "가장 싼 값"으로 뽑지 않는다.
- **연결된 기록**: 6-1의 두 길로 이어진 내역. "우리가 산 값"으로 바로 보여 준다(날짜, 산 사람, 곳·플랫폼, 개당 가격, 용량이 있으면 100g·1개당 가격).
- **이름이 비슷한 우리 기록**: 연결은 없지만 가계부 품목(`transaction_items.name`) 이름이 비슷한 것(예: 통합 전 쿠팡 주문). 따로 묶고 가계부에 적힌 원래 상품명·용량·날짜를 그대로 보여 준다. 고른 상품과 같은 줄처럼 놓지 않는다(가격 확인 설계 2절 실패 조건: 다른 용량을 같은 상품처럼 놓기).
  - 줄마다 "같은 상품 맞아요" / "아니에요". 고른 결과는 가구 단위로 기억한다(가격 확인 설계 4-3의 다른 출처 연결 규칙과 같음). "맞아요"는 연결 기록과 같은 묶음으로 올리고, "아니에요"는 다시 보여 주지 않는다.
- 읽기: 가계부 표는 가계부 RLS(같은 가구만) 아래에서 로그인한 사용자 권한으로 읽는다. 장보기 쪽에 읽기 함수(`grocery` 스키마, `security invoker`)를 둘지 앱에서 바로 읽을지는 [빌더]. 어느 쪽이든 `public` 표에는 쓰지 않는다.
- 단위당 가격은 가계부가 저장해 둔 `pack_size`·`pack_unit`·`unit_price`에서 계산한다. 없으면 "용량 확인 못 함"이다. 지어 내지 않는다.
- "어디서 살지" 보기의 매장 기준 가격(화면 설계 7-2: 참가격 → 우리가 산 매장 값)에는 연결 기록과 "맞아요"를 누른 기록만 쓴다.

### 6-3. 분류 [사용자: 두 체계 유지 + 대응표]

- 장보기 11개(정육·수산·채소·과일·유제품·계란·가공·냉동·음료·생활용품·기타)는 그대로 둔다. 매장 동선 묶음, DB check 제약(`grocery.items.category`), 식약처 대조, 신선 품목 판단(다나와 대신 시세)이 이 값에 기댄다.
- 가계부 내역이 될 때(6-1 길 ②) 대응표:

| 장보기 분류 | 가계부 분류 |
|---|---|
| 정육·수산·채소·과일·유제품·계란·가공·냉동·음료 | 장보기 |
| 생활용품 | 가계부 이름 규칙(`src/lib/categorize.ts`)의 제안. 예: 세제·휴지 → 세제·소모품, 수세미·고무장갑 → 욕실·청소. 제안이 없으면 생활용품 |
| 기타 | 가계부 이름 규칙의 제안. 없으면 장보기 |

- 가계부 분류는 가구마다 숨기거나 바꿀 수 있다. 대응한 분류가 그 가구에 없거나 숨겨져 있으면 '장보기'로 한다. 그것도 없으면 분류 없이 둔다 [제안].
- 저장 전 확인 화면에서 품목마다 바꿀 수 있다(가계부 분류 칩).
- 길 ①(스마트 입력)은 지금 가계부 규칙대로 분류한다. 장보기와 연결된다고 바꾸지 않는다.

## 7. 옮기는 순서와 그동안 쓰기 [사용자: 통합 먼저]

옮기는 동안(1~3단계) 장보기 저장소에는 새 기능을 넣지 않는다. 두 사람은 예전 장보기 앱을 그대로 써도 된다. 두 앱이 같은 DB를 보므로, 가계부 장보기 탭에서 담은 것이 예전 앱에도 실시간으로 보인다.

| 단계 | 하는 일 | DB | 끝났다고 보는 기준 |
|---|---|---|---|
| 1. 옮기기 | 4절 구조로 장보기 코드·테스트·마이그레이션 파일·함수 소스·`config.toml`·식약처 워크플로·문서를 가계부 저장소로. 탭·톱니 버튼·`?tab=grocery`. 장보기 화면 동작은 그대로 | 바꾸지 않음 | `npm test`·`npm run build` 통과. 장보기 테스트가 실제 마이그레이션 위에서 통과. 390·1280px 라이트·다크 캡처(장보기 + 가계부 다섯 화면)를 보고 고침 |
| 2. 배포·확인 | `main` 병합·푸시(사용자 지시) → 가계부 배포. 가계부 쪽 식약처 워크플로 수동 실행 `200` 확인 | 바꾸지 않음 | 두 기기에서 장보기 탭: 담기, 실시간 반영, 후보 고르기, 가격, 식약처 경고가 예전 앱과 같음(사용자) |
| 3. 예전 앱 정리 | 장보기 저장소: ① 안내 페이지를 마지막으로 배포(아래) ② 식약처 워크플로 끄기 ③ 저장소 보관 | 바꾸지 않음 | 예전 주소를 열면 안내 페이지가 뜨고 가계부 장보기 탭으로 넘어감. 홈 화면 장보기 아이콘은 사용자가 지움 |
| 4. 장 본 것 → 가계부 | 6-1, 6-3 | `grocery` 스키마에 연결 칸 등 추가(사용자 확인 후 MCP 적용) | 별도 계획의 완료 기준 |
| 5. 우리가 산 값 | 6-2 | 필요하면 `grocery` 스키마에 "맞아요/아니에요" 기억 표 | 별도 계획 |
| 6. 장보기 남은 계획 | ④ 나머지, ③ 시세(탭 안 "목록 \| 시세"), 사진·바코드 | 각 계획대로 | 각 계획대로 |

4·5단계와 6단계의 순서는 그때 정한다.

**3단계 안내 페이지** [사용자]:

- 장보기 저장소 `main`의 앱을 한 장짜리 `index.html`로 바꿔 마지막으로 배포한다. 내용은 "장보기가 가계부 앱으로 옮겨졌어요" 문장과 가계부 장보기 탭으로 가는 링크이고, 자동으로 그 주소로 넘어간다. 가계부 디자인 규칙대로 그림·반짝이 없이 문장과 버튼만 둔다.
- 설치된 장보기 PWA는 서비스 워커가 예전 앱 파일을 캐시하고 있다. 지금 장보기 앱은 "앱으로 돌아올 때 새 버전 확인 → 새로 고침"(1a8e718)을 하므로, 마지막 배포 뒤 앱을 한 번 열면 안내 페이지를 받을 것으로 본다(추측입니다. 3단계에서 실제 기기로 확인). 안내 페이지에서는 서비스 워커를 등록 해제해 캐시가 남지 않게 한다 [빌더].
- 보관(archive)하면 저장소는 읽기 전용이 되어 푸시할 수 없다([GitHub 문서](https://docs.github.com/en/repositories/archiving-a-github-repository/archiving-repositories)). 보관해도 Pages 사이트는 내려가지 않는다([GDS 저장소 정리 안내](https://docs.publishing.service.gov.uk/manual/retiring-a-repo.html)). 보관한 저장소에서 예약 실행이 멈추는지는 찾지 못했다(모름). 그래서 보관 전에 워크플로를 직접 끈다.
- 장보기 저장소의 문서·결정 기록은 보관된 저장소에도 남고, 이어지는 기록은 가계부 `docs/grocery/`에서 한다.

## 8. 확인 필요

1. 가계부 Edge Function `extract-entries`·`export-csv`의 지금 `verify_jwt` 설정(대시보드). 장보기 `config.toml`을 옮기면 저장소에서 함수를 배포할 때 이 파일이 쓰이므로, 가계부 두 함수 설정이 바뀌지 않게 같은 파일에 적는다.
2. 1단계 뒤 가계부 화면에서 겹치는 클래스 10개가 서로 새지 않는지 캡처로 비교.
3. 3단계 안내 페이지 배포 뒤, 홈 화면에 설치한 장보기 앱이 실제 기기(iPhone Safari PWA)에서 안내 페이지로 바뀌는지.
4. 보관한 저장소에서 예약 실행이 도는지. 워크플로를 먼저 끄므로 결과와 상관없지만, 보관 뒤 Actions 화면에서 한 번 본다.
5. 6-1 길 ①의 이름 맞추기 정확도. 실제 영수증 상품명(예: "CJ비비고왕교자1.05kg")과 장보기 품목 이름(예: "만두")이 얼마나 맞는지는 실제 영수증으로 확인한다.

## 9. 결정 기록에 남길 것

## 10. 만드는 사람에게 맡기는 것 [빌더]

- `GroceryTab`이 장보기 탭이 안 보일 때도 살아 있을지(실시간 구독 유지) 아니면 탭을 열 때마다 다시 읽을지. 장보기 목록은 화면 복귀 때 다시 읽으므로 어느 쪽이든 맞춰진다.
- 설정 화면 여는 방식, 장보기 탭 아이콘, 앱 안 탭 전환 때 주소 바꾸기.
- 가계부 CSS가 장보기 안으로 새는 것을 막는 방법(4-3).
- 6-1 연결 칸의 이름과 품목 단위 연결 여부, 길 ①의 이름 맞추기 규칙, 길 ②의 시트 세부.
- 6-2 읽기 함수 여부와 "맞아요/아니에요" 기억 표 설계.
