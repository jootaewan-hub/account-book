# 레시피 탭 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 유튜브·쇼츠 주소를 앱에 붙여넣으면 맥 처리기가 읽어 레시피로 정리·검증하고, 앱 '레시피' 탭과 구글 드라이브·옵시디언에 보관한다.

**Architecture:** 앱은 `recipe.inbox`에 주소만 넣는다. 맥의 Node 처리기(launchd)가 서버 함수 `recipe-worker`(비밀 헤더, 서비스 롤)로 일을 받아 yt-dlp·whisper.cpp·ffmpeg·macOS 글자 인식으로 근거를 모으고, `claude -p`로 정리한 뒤 코드 검사와 두 번째 읽기로 검증해 돌려준다. 계약(zod)과 단위·분류 규칙은 `supabase/functions/_shared/recipe*.ts` 한 벌을 앱·서버 함수·처리기가 같이 쓴다.

**Tech Stack:** React 19 + TS 7 + Vite PWA, Supabase(Postgres RLS, Edge Functions/Deno, Realtime), zod 4, vitest 5 + PGlite 0.5 + jsdom, Node 25(타입 지우기로 `.ts` 직접 실행), yt-dlp + Deno, whisper.cpp 1.9.5, ffmpeg, Swift Vision, Claude Code CLI, Google Drive/Sheets REST.

**Spec:** `docs/superpowers/specs/2026-11-19-recipes-design.md` (결정 번호 N번은 `docs/recipes/tracking/brainstorm.md`)

## Global Constraints

- 사용자와 문서, 화면 글은 한국어. 화면에 "AI", "분석 중", 반짝이 아이콘, 채팅창을 쓰지 않는다. 진행 글은 정확히: "영상 정보 받는 중", "자막 받는 중", "말 받아쓰는 중", "화면 글자 읽는 중", "레시피 정리 중", "다시 읽어 맞춰 보는 중", "저장 중".
- 출처 숫자(분량·인분·시간)는 `description`·`caption_manual`·`caption_auto`·`asr`·`screen`·`user`에서만. 덧붙인 값(`suggested_*`, `servings_suggested`, `editor_tip`, 용어 풀이 덧붙임)은 출처 `editor`로 따로 두고 출처 숫자 칸에 넣지 않는다(DB 제약 포함).
- 단위는 출처 표기 그대로 적는다. 큰술·T = 15ml, 작은술·t = 5ml. 컵 등은 공식 출처를 찾기 전까지 ml를 붙이지 않는다.
- 분류 낱말: 요리 종류 `한식, 양식, 일식, 중식, 기타`(1개), 난이도 `쉬움, 보통, 어려움`(1개), 주재료·조리법·상황은 계약 v1 낱말 그대로. 폴더 `레시피/<요리 종류>/<첫 주재료>/<첫 조리법>/<난이도>/`.
- 인분은 1~8인분. 기준은 출처 인분, 없으면 덧붙인 인분(그때 "기준 N인분(덧붙임, 영상에 인분 없음)"). g·ml 정수, 그 밖의 단위 ¼ 분수 반올림. 화면에서만 계산.
- 영상·소리·장면·자막·받아쓰기 원문은 저장소·DB·드라이브·옵시디언에 넣지 않는다. 처리기 작업 폴더는 `~/Library/Caches/recipe-worker/<일 id>/`, 끝나면 지우고 실패는 하루 둔다. 공개 저장소에 보관함 이름·Google 프로젝트 id·계정·실제 자막을 넣지 않는다(시험 자료는 만든 글).
- 레시피 마이그레이션은 `recipe` 스키마만 만들고 바꾼다. `public`은 참조·읽기만, `grocery`는 건드리지 않는다. 장보기로 쓰는 길은 앱의 로그인한 사용자가 `grocery.items`에 넣는 것 하나.
- 마이그레이션 파일 이름은 적용 직전 `origin/main`의 가장 늦은 파일보다 뒤여야 한다(지금 `20261121000000_refunds.sql`). 공유 DB 적용은 Supabase MCP `apply_migration`만, 사용자 확인 뒤.
- `claude -p`는 실행 파일 전체 경로로 부르고, 도구는 그 일의 작업 폴더 `Read`만 허락한다. 결과는 계약 검사만 하고 실행하지 않는다.
- 처리기 비밀·구글 갱신 토큰은 `~/.config/recipe-worker/`(권한 600), 로그에 쓰지 않는다. 서비스 롤 키는 서버에만.
- 장보기 CSS 규칙처럼 레시피 CSS는 `.recipes` 안에서만 먹는다. UI를 바꾸면 `npm run screens`로 390·1280px, 라이트·다크를 보고 끝낸다.
- 공유 DB 적용, 함수 배포, 처리기 설치, 구글 허락, main 병합은 Task 25에서 한 번에 사용자에게 묻는다. 그 전 작업은 브랜치 `claude/recipes-docs`에서 커밋만 한다.

## Review Focus

1. **여러 꼴의 유튜브 주소**(`youtu.be/ID?si=…`, `m.youtube.com/watch?v=ID&t=30s`, `/shorts/ID/`, `music.youtube.com`, 재생목록 `list=`만 있는 주소, `/live/ID`)를 붙여넣으면 같은 영상은 같은 열쇠가 되고, 영상이 아닌 주소는 거절되어야 한다 → Task 2.
2. **한국어로 적힌 분량**("한 큰술 반", "1과 1/2", "반 개", "1.5T", "두세 큰술")이 근거에 있으면 숫자를 지우지 말아야 한다. 범위 표현은 숫자 대신 원래 표현으로 남는다 → Task 11.
3. **맥이 처리 중에 잠들거나 처리기가 죽으면** 일이 "처리 중"에 영원히 남지 않고 3분 뒤 다시 가져가지며, 사용량 제한으로 미룬 일은 시도 횟수를 쓰지 않는다 → Task 5·9.
4. **두 사람이 같은 영상을 거의 동시에 담으면** 대기 줄은 하나만 생기고 두 번째 사람에게 "이미 담겨 있어요"가 보인다 → Task 5·17.
5. **처리기가 사본을 쓰는 동안 앱에서 분류를 바꾸면** 다음 차례에 옛 자리의 파일이 옮겨지고 같은 레시피 파일이 둘 생기지 않는다 → Task 16.
