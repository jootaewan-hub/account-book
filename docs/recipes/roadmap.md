# 레시피: 단계

2026-11-19 승인된 설계 뒤 다시 썼다. 처음 R0~R8(2026-11-18)은 읽기를 Claude Code와 claude.ai가 하던 때의 순서라 버렸다. 구현 순서와 상태는 `docs/superpowers/plans/2026-11-19-recipes.md`(계획)와 `tracking/status.md`(지금 상태)에 있다.

## 만든 순서

설계(`docs/superpowers/specs/2026-11-19-recipes-design.md`)의 "먼저 돌아가게 만들 조각"을 이 순서로 만들었다. 네 조각(DB, 서버 함수, 처리기, 앱)을 모두 로컬에서 만들고 시험했다.

| 조각 | 내용 | 상태 |
|---|---|---|
| 1 | 계약 v2, 순수 규칙(주소 정규화, 단위·인분, 분류·난이도), DB(`recipe` 스키마, 대기함, 등록 함수), 서버 함수 `recipe-worker` | 코드 끝 |
| 2 | 맥 처리기: 수집(L0~L3), 정리, 기계 검사, 두 번째 읽기와 맞춰 고치기 | 코드 끝, 실제 영상으로는 아직 |
| 3 | 앱 '레시피' 탭: 레시피북, 담기, 상세, 인분 바꾸기, 확인 화면, 요리 화면, 고치기 | 코드 끝, 화면 캡처 확인함 |
| 4 | 가진 재료, 만들 수 있는 요리, 모자란 재료 장보기에 담기 | 코드 끝 |
| 5 | 구글 드라이브·옵시디언 사본, 처리기 설치(`install.sh`)와 점검(`doctor`) | 코드 끝, 실제 쓰기는 아직 |

## 남은 것 (순서대로)

1. **실제 영상 확인(승인 Task 14).** 설치 허락이 필요하다: yt-dlp, Deno, whisper.cpp 한국어 모델(약 1.6GB). 구독 사용량도 쓴다. 기준 답안 영상 `AkX6uA4BaDs`, 간장두부조림, 설명란에 분량이 있는 쇼츠, 설명란이 빈 쇼츠로 설계 §12의 "끝까지 한 번"을 돌린다. 세는 것: 맞힌 숫자, 빠뜨린 숫자, 어느 출처에도 없는 숫자(0이어야 함). 집과 회사 인터넷에서 각각(A1), launchd에서 Claude 실행(A2)과 사용량(A2), 받아쓰기(A3)와 글자 인식(A4)을 함께 확인한다. A1이나 A2가 안 되면 멈추고 사용자에게 묻는다.
2. **한 번에 묻기(Task 25).** 그 전에 서버 함수의 요청 횟수 한도를 넣는다(설계 요구, 아직 없음). 마이그레이션 셋 적용(Supabase MCP `apply_migration`), `recipe-worker` 배포와 서버 비밀 값, 대시보드 Exposed schemas에 `recipe` 더하기, 옵시디언 보관함 만들기, 구글 로그인(A6), 처리기 설치(`~/Library/LaunchAgents`에 plist), main 병합과 버전 올리기(D-028). 그 뒤 실제 맥 → 서버 → 앱으로 끝까지 한 번 돌고, 배포를 마치면 릴리스 내용을 사용자에게 정리해 보인다.
3. **확인을 미룬 것.** A2(launchd로 도는 처리기가 Claude를 부름)와 A5(launchd로 도는 처리기가 iCloud 옵시디언 폴더와 구글 드라이브에 씀)는 위 1·2가 끝나야 한다.
