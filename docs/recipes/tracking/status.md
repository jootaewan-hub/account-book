### Task 25: 한 번에 묻기 (끝까지 한 번과 배포)

모두 사용자가 허락한 것만 차례로 한다.

1. 마이그레이션 다섯을 적용한다. 앞의 넷(`*_recipe_init`, `*_recipe_import`, `*_recipe_pantry`, `*_recipe_rate`)은 Supabase MCP `apply_migration`으로, 마지막 `20261122040000_recipe_import_fn.sql`(등록 함수 `import_recipe`, `delete` 문장이 있어 MCP가 거절한다)은 사용자가 SQL 편집기에서 적용하고 `pg_proc`로 확인한다. 이름 순서대로 적용한다. 적용 직전에 `origin/main`의 가장 늦은 마이그레이션보다 뒤 시각인지 다시 확인한다.
2. Edge Function `recipe-worker` 배포(커밋 고정 stub)와 서버 비밀 `RECIPE_WORKER_SECRET`. 값은 맥에서 만들어 파일로 건넨다. 배포 뒤 `verify_jwt`가 `supabase/config.toml`과 같은지, 비밀 없이 부르면 401인지 확인한다.
3. Supabase 대시보드의 Exposed schemas에 `recipe` 더하기(사용자).
4. 옵시디언: iCloud에 새 보관함을 만들기(사용자).
5. 구글 로그인(처리기용 OAuth, 사용자가 한 번 로그인해 허락).
6. 처리기 설치: `tools/recipe-worker/install.sh <커밋>`이 `~/Library/Application Support/recipe-worker/`에 설치하고 `~/Library/LaunchAgents/local.recipe-worker.plist`를 둔다(불러오는 것은 사용자가 따로). macOS가 폴더 접근을 물으면 허락한다.
7. 끝까지 한 번: 앱에서 기준 영상을 붙여넣어 맥 → 서버 → 앱으로 레시피가 들어오는지, 드라이브·옵시디언에 사본이 쓰이는지 본다.
8. main 병합·푸시(= 배포)와 버전 올리기(`src/lib/changelog.ts`, `package.json`, D-028). 배포를 마치면 릴리스 내용을 사용자에게 정리해 보인다.

## 열린 문제

- Task 14(2026-11-19)에서 나온 것과 처리 상태:
  1. 사용량 기록: 처리기가 `claude -p`의 사용량을 버렸다. **고침(R1)**: 호출마다 받아 일마다 합하고 건조 실행 요약과 처리기 기록 한 줄에 남긴다. 레시피 하나의 실제 사용량은 다음 실제 시험에서 잰다.
  2. 긴 영상의 화면 글자·장면 한도 때문에 뒤쪽 근거를 못 봤다("07:00 이후 잘림"). **고침(R2)**: 한도는 그대로 두고 영상 전체에서 고르게 고른다. 고친 뒤 실제 영상으로 다시 돌려 보지 않았다(확인 필요).
  3. 화면에서 읽은 분량의 단위가 빠졌다(`FgKy9Xq4LKY --no-description`). **고침(R3)**: 세는 재료가 아니면 확인 필요 "단위를 읽지 못했어요". 정리 프롬프트가 화면의 단위를 왜 비웠는지는 모른다(확인 필요).
  4. 통깨가 "다른 곳"이 아니라 화면 근거 재료(`참깨`)로 올라갔고, 계량 도구가 근거 없이 "밥숟가락"이었다. **계량 도구는 고침(M9)**: 근거 글에 도구의 말이 없으면 "확인 못 함". 통깨는 그대로다(기준 답안과 다른 판단, 확인 필요).
  5. 처리기가 `~/.claude`의 설정·스킬·CLAUDE.md를 읽어 호출마다 토큰이 많이 붙었다. **고침(I4)**: 격리 인자로 같은 작은 호출의 입력이 20,798 → 7,776 토큰. 모델은 정하지 않아 기본 모델이 쓰인다(설정 `claudeModel`, 정하는 것은 사용자 판단).
- 맥으로 걸리는 시간: 집 인터넷 기준 영상 13분 13초 → 265초, 19분 29초 → 265초, 쇼츠 141~216초(2026-11-19). 하루 한도 15(설정에서 바꿈)는 처음값이다.
- 구독으로 사람 없이 돌리는 것이 이용 조건에 맞는지는 확인 필요(A2, 사용자 판단). 공식 문서는 "ordinary, individual usage"를 전제로 한다고만 한다.
- 처리기 환경에 `USER`가 없으면 CLI가 구독 로그인을 찾지 못한다(2026-11-19 확인). 처리기는 없으면 채우지만, launchd에서 실제로 되는지는 Task 25 설치 뒤 확인 필요.
- 화면에만 분량이 나오는 쇼츠: 설명란을 숨긴 실행에서 화면 분량 5개가 모두 맞았다(단위는 빠짐). 설명란이 빈 쇼츠는 화면에 분량표가 없었다.
- 컵·종이컵 같은 나머지 단위의 기준 부피는 공식 출처를 찾지 못했다. 그래서 큰술(15ml)·작은술(5ml)만 ml를 붙이고, 그것도 계량스푼으로 확인된 레시피에서만 보인다.
- 아이폰 홈 화면 앱에서 Screen Wake Lock(요리 화면 꺼짐 방지)이 되는지는 확인 필요다.
- 스프레드시트 API가 `drive.file` 권한으로 처리기가 만든 시트를 고칠 수 있는지는 확인 필요(Task 25에서 시도, 안 되면 목록을 CSV로 올린다).
- 구글 OAuth 앱이 "Testing" 상태면 갱신 토큰이 7일 뒤 끊긴다(공식 문서로 확인, A6). 그래서 앱을 "프로덕션"으로 두고 `drive.file`만 쓴다. 프로덕션 전환 때 비민감 범위의 심사 여부는 확인 필요.
- 맥 처리기가 사본(드라이브·옵시디언)을 못 쓰면 앱의 처리 줄 아래에 "사본: …" 한 줄이 보인다(I7). 처리기를 켤 때 두 곳을 시험한다(A5). launchd에서의 실제 동작은 Task 25 설치 뒤 확인한다.
- 앱의 캡처용 가짜 서버(`scripts/screenshots.mjs`)는 같음 조건만 거른다. 치운 실패 일(`dismissed_at is null` 거르기)은 캡처로 볼 수 없어 시험(`tests/components/recipesBook.test.tsx`)으로만 본다.
- 난이도 점수 경계(재료 8·14개, 단계 6·11개)는 실제 레시피를 넣어 본 뒤 고칠 수 있다.
- 구현에서 정하고 문서에 남긴 것: 같은 날 yt-dlp 다시 시도는 뺐고(하루 첫 호출 전에 갱신함), 처리기 점검(`doctor`)의 서버 확인은 "살아 있음" 표시를 갱신한다.
- 로컬이 `origin/main`보다 뒤처졌을 수 있다(Codex가 main에 직접 올린 변경이 있었다). 병합 전에 `git fetch`로 확인하고 버전 번호는 그때의 main을 보고 정한다.
