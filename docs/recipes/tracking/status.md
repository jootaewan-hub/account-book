## 사용자 승인을 기다리는 일

### Task 14: 실제 영상 확인 (설치 허락과 구독 사용 허락)

- 설치: yt-dlp, Deno(`brew`), whisper.cpp 한국어 모델 `large-v3-turbo`(약 1.6GB, 확인 필요). ffmpeg·whisper.cpp는 이미 있고 글자 인식은 macOS에 들어 있다.
- 구독 사용량을 쓴다(레시피 하나에 얼마나 드는지 잰다).
- 확인할 것(설계 "이 설계가 기대는 것"): A1 집·회사 인터넷에서 유튜브 받기, A2 `claude -p`의 사용량과 장면 그림 읽기, A3 받아쓰기, A4 화면 글자 인식, A6 구글 OAuth "테스트" 상태의 토큰 기간과 시트 API. 기준 영상 `AkX6uA4BaDs`, 간장두부조림, 설명란에 분량이 있는 쇼츠, 설명란이 빈 쇼츠로 맞힌 숫자·빠뜨린 숫자·근거 없는 숫자(0이어야 함)를 센다.
- A1이나 A2가 안 되면 대신 갈 길(Gemini, 서버 Anthropic 키)로 바로 가지 않고 멈추고 묻는다. A1이 통과하면 사용자 승낙을 받아 Gemini 시험용으로 만들어 둔 Google AI Studio 프로젝트와 키를 지운다.
- 회사 인터넷 확인은 평일 낮에 돌려야 한다.

### Task 25: 한 번에 묻기 (끝까지 한 번과 배포)

모두 사용자가 허락한 것만 차례로 한다.

1. 마이그레이션 셋을 Supabase MCP `apply_migration`으로 적용(`*_recipe_init`, `*_recipe_import`, `*_recipe_pantry`). 적용 직전에 `origin/main`의 가장 늦은 마이그레이션보다 뒤 시각인지 다시 확인한다.
2. Edge Function `recipe-worker` 배포(커밋 고정 stub)와 서버 비밀 `RECIPE_WORKER_SECRET`. 값은 맥에서 만들어 파일로 건넨다. 배포 뒤 `verify_jwt`가 `supabase/config.toml`과 같은지, 비밀 없이 부르면 401인지 확인한다.
3. Supabase 대시보드의 Exposed schemas에 `recipe` 더하기(사용자).
4. 옵시디언: iCloud에 새 보관함을 만들기(사용자).
5. 구글 로그인(처리기용 OAuth, 사용자가 한 번 로그인해 허락).
6. 처리기 설치: `tools/recipe-worker/install.sh <커밋>`이 `~/Library/Application Support/recipe-worker/`에 설치하고 `~/Library/LaunchAgents/local.recipe-worker.plist`를 둔다(불러오는 것은 사용자가 따로). macOS가 폴더 접근을 물으면 허락한다.
7. 끝까지 한 번: 앱에서 기준 영상을 붙여넣어 맥 → 서버 → 앱으로 레시피가 들어오는지, 드라이브·옵시디언에 사본이 쓰이는지 본다.
8. main 병합·푸시(= 배포)와 버전 올리기(`src/lib/changelog.ts`, `package.json`, D-028). 배포를 마치면 릴리스 내용을 사용자에게 정리해 보인다.

### 확인을 미룬 것

- **A2 launchd 실행:** launchd로 도는 처리기가 `claude -p`를 부르는지(실행 파일 전체 경로, 셸 별칭 없음). 위 설치 뒤에 확인한다.
- **A5 iCloud·드라이브 쓰기:** launchd로 도는 처리기가 iCloud 옵시디언 폴더와 구글 드라이브에 쓰는지(macOS 개인정보 보호 창으로 조용히 실패할 수 있음). `doctor` 명령이 시험 파일을 만들고 지워 확인한다. 설치와 구글 로그인 뒤에 한다.

## 열린 문제

- 실제 영상으로 돌려 본 적이 없다. 정리·검증 흐름은 만든 자료(공개 저장소라 실제 자막을 넣지 않음)와 가짜 응답으로만 시험했다.
- 맥으로 걸리는 시간과 구독 사용량은 모른다(A2). 하루 한도 15(설정에서 바꿈)는 처음값이다.
- 구독으로 사람 없이 돌리는 것이 이용 조건에 맞는지는 확인 필요(A2).
- 화면에만 분량이 나오는 쇼츠를 장면 24장 안쪽으로 충분히 읽는지 모른다(A4).
- 컵·종이컵 같은 나머지 단위의 기준 부피는 공식 출처를 찾지 못했다. 그래서 큰술(15ml)·작은술(5ml)만 ml를 붙이고, 그것도 계량스푼으로 확인된 레시피에서만 보인다.
- 아이폰 홈 화면 앱에서 Screen Wake Lock(요리 화면 꺼짐 방지)이 되는지는 확인 필요다.
- 스프레드시트 API가 `drive.file` 권한으로 처리기가 만든 시트를 고칠 수 있는지는 확인 필요(안 되면 목록을 CSV로 올린다).
- 구글 OAuth 앱이 "테스트" 상태면 갱신 토큰이 7일 뒤 끊긴다고 알고 있다(확인 필요, A6). 그러면 앱을 "프로덕션"으로 두고 `drive.file`만 쓴다.
- 난이도 점수 경계(재료 8·14개, 단계 6·11개)는 실제 레시피를 넣어 본 뒤 고칠 수 있다.
- 구현에서 정하고 문서에 남긴 것: 같은 날 yt-dlp 다시 시도는 뺐고(하루 첫 호출 전에 갱신함), 서버 함수의 요청 횟수 한도는 두지 않았다(1MB 크기 한도만), 처리기 점검(`doctor`)의 서버 확인은 "살아 있음" 표시를 갱신한다.
- 로컬이 `origin/main`보다 뒤처졌을 수 있다(Codex가 main에 직접 올린 변경이 있었다). 병합 전에 `git fetch`로 확인하고 버전 번호는 그때의 main을 보고 정한다.
