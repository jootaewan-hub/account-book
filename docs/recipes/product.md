# 레시피: 무엇을 만드는가

> **2026-11-18 브레인스토밍으로 일부가 낡았다.** 바뀐 내용과 낡은 곳은 `tracking/brainstorm.md`에 있고, 그 문서가 우선한다. 설계 문서가 승인되면 이 문서를 고친다.

부부 두 사람이 쓰는 레시피북이다. 가계부 앱 안의 한 부분으로, 장보기와 이어진다.

## 요구사항 (사용자 말 요지, 2026-11-18)

- 요리 레시피 영상(유튜브, 유튜브 쇼츠, 인스타 릴스)이나 요리 방법을 올리면 재료와 레시피를 자세히 읽어 정리한다.
- 어떻게 만들면 좋을지를 정리하고, 분류해서 레시피북으로 쌓는다.
- 가진 재료로 어떤 요리를 할 수 있는지 보여 준다(쿡앱의 원래 목표).
- Claude Code와 claude.ai를 함께 써서 만들고 운영한다.

## 쓰는 흐름 네 가지

1. **담기.** 영상 주소를 건넨다. PC에서는 Claude Code에, 밖에서는 claude.ai나 앱의 대기함에. 읽은 결과는 "검토 대기"로 들어온다.
2. **검토.** 확인이 필요한 곳(출처끼리 다른 곳, 흐리게 들린 말, 덧붙인 값)만 보고 고친 뒤 레시피북에 넣는다.
3. **요리.** 레시피를 열어 분량을 맞추고, 단계를 따라간다. 단계마다 영상의 그 장면으로 갈 수 있다.
4. **뭐 해 먹지.** 가진 재료를 기준으로 지금 만들 수 있는 요리와 한두 가지만 사면 되는 요리를 본다. 모자란 재료는 장보기 목록에 담는다.

## 화면 목록 (설계 전 초안, R3·R4·R7에서 설계)

| 화면 | 내용 |
|---|---|
| 레시피북 | 저장한 레시피 목록. 찾기, 분류(요리 종류·주재료·조리법·상황), 즐겨찾기. 맨 위에 검토 대기 수 |
| 레시피 상세 | 재료(묶음별, 분량 배수), 순서(불 세기, 넘어가는 신호, 영상 시각), 비율·원리, 우리 집 메모, 출처와 읽은 날 |
| 검토 | 확인이 필요한 곳만 모아 보기. 출처끼리 다른 곳은 둘 다 보이고 하나를 고른다. 다 보면 레시피북에 넣기 |
| 요리 모드 | 한 단계씩 큰 글씨, 화면 꺼짐 방지, 시간이 있는 단계의 타이머, 재료 체크 |
| 담기 | 주소를 대기함에 넣기, 글 붙여넣기, 사진으로 넣기, 직접 쓰기 |
| 뭐 해 먹지 | 가진 재료 고르기(늘 있는 양념 따로), 만들 수 있는 요리 순, 모자란 재료 → 장보기에 담기 |

## 지킬 성격

- 숫자는 출처가 있는 것만. 출처가 무엇인지 늘 보인다(가계부·장보기의 출처 태그와 같은 방식).
- 영상을 본 사람이 쓴 요약이 아니라, 다시 영상을 보지 않아도 요리할 수 있는 작업 지시서.
- 원본 영상을 대신하지 않는다. 출처 링크와 단계별 시각을 앞에 둔다.
- 디자인은 가계부 `DESIGN.md`와 `docs/grocery/DESIGN.md`를 따르고, 레시피에만 필요한 것을 `docs/recipes/DESIGN.md`에 더한다(R3에서 작성).

## 하지 않을 것

- 공개 서비스, 레시피 공유·검색 사이트. 두 사람만 쓴다.
- 영상·자막 원문 보관. 정리한 결과와 출처만 남긴다.
- 앱 서버가 영상 사이트를 긁어 오는 것. 읽는 일은 Claude Code와 claude.ai가 한다(P-02).
- 쿡앱의 8만 건 영문 레시피, 풍미 과학(화합물·임베딩), 검색 서버(Typesense). `cookapp-absorb.md` 참고.
- 영양 계산. 장보기의 성분 탭이 이미 식약처 자료를 쓰고 있어 필요해지면 그쪽과 잇는다.
