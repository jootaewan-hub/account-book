## 레시피 부분

범위: `src/recipes/`, `tests/recipes/`, `supabase/migrations/*_recipe_*.sql`, `docs/recipes/`, `.claude/skills/recipe-ingest/`.

레시피 일을 시작하기 전에 `docs/recipes/tracking/status.md`(현재 단계·확정할 결정·열린 문제)를 본다. 영상이나 글에서 내용을 가져오는 일은 `docs/recipes/ingest-sources.md`의 "확인된 사실"과 "확인 필요"를, 읽은 것을 정리하는 일은 `docs/recipes/extraction-rules.md`를 먼저 본다. 등록 자료의 모양은 `docs/recipes/contract/recipe.schema.json` 하나가 기준이다.

### 반드시 지킬 것 (레시피 부분)

- **분량·인분·시간의 숫자는 출처에 있는 값만 낸다.** 설명란, 자막, 화면, 음성에 없으면 비워 두고 "약간" 같은 원래 표현을 그대로 둔다. 우리가 덧붙인 값은 `suggested_*`와 `editor_tip`에만 넣고 화면에서 "덧붙임"으로 구분한다. 2차 자료(기사·블로그 정리)의 숫자는 분량으로 쓰지 않는다.
- **모든 재료와 단계에는 출처(`origin`)가 있다.** 출처끼리 다르면 하나를 조용히 고르지 않고 `conflicts`에 둘 다 남긴다.
- **자막·받아쓰기 원문, 내려받은 영상·음성을 저장소와 DB에 넣지 않는다.** 이 저장소는 공개다. 작업 파일은 `.recipe-cache/`(gitignore)에만 두고, 영상·음성은 읽은 뒤 지운다. 단계 설명은 우리 말로 다시 쓰고 영상 주소와 시작 시각을 남긴다.
- **로그인 정보를 저장소에 두지 않는다.** 인스타그램 쿠키 파일은 저장소 밖에 두고, 본계정 쿠키는 쓰지 않는다. 쿠키가 필요한 영상은 사용자에게 먼저 묻는다.
- **레시피 마이그레이션은 `recipe` 스키마만 바꾼다.** `public`·`grocery`의 표는 참조·읽기만 한다. 장보기 목록에 재료를 담는 것은 로그인한 사용자 권한의 `grocery.items` 넣기 하나뿐이다. `tests/recipes/boundary.test.ts`가 검사한다.
- **등록은 `recipe.import_recipe()` 하나로만 한다.** Supabase MCP로 표에 직접 넣거나 고치지 않는다. 부르기 전에 넣을 내용의 요약(제목, 재료 수, 확인 필요 수)을 사용자에게 보여 준다.
- **AI처럼 보이지 않게 만든다.** 화면에 "AI", 반짝이, "분석 중"을 쓰지 않는다. 출처 태그는 "설명란", "영상 말", "화면 글자", "덧붙임"처럼 어디서 온 값인지 그대로 적는다.
- **외부 도구는 조심해서 쓴다.** yt-dlp는 쓰기 전에 최신으로 올린다. 한 번에 여러 영상을 몰아서 받지 않는다. 받지 못하면 우회하지 말고 사용자에게 알린다.
- **레시피 CSS는 `.recipes` 안에서만 먹는다.** 장보기의 `.grocery` 규칙과 같다.

### 문제를 만나면 (레시피 부분)

다음은 발견 즉시 사용자에게 알린다.

- 화면의 분량·시간이 출처와 다르거나 출처 없이 표시되는 것을 발견했을 때.
- 자막 원문, 영상·음성 파일, 쿠키가 저장소나 DB에 들어간 것을 발견했을 때.
- 다른 가구가 레시피·가진 재료·대기함을 읽을 수 있는 경로를 발견했을 때.

그 밖의 미해결 문제는 `docs/recipes/tracking/status.md`의 "열린 문제"에 적는다.
