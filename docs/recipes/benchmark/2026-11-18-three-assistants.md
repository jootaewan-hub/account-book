# 같은 영상, 세 도우미 (2026-11-18)

대상: 셰프호윤 「한식 일타강사의 기사식당 제육볶음 레시피」(`youtube:AkX6uA4BaDs`, 13분). 같은 부탁("재료와 레시피를 자세히 정리해 줘")을 Claude(claude.ai), Gemini, ChatGPT에 했다. Gemini와 ChatGPT의 결과는 사용자가 붙여 넣은 글로 봤다(Gemini의 재료 표는 붙여 넣은 글에 빠져 있었다).

이 영상의 정답 근거: 설명란에 재료 15가지의 분량과 13단계가 있다. 영상 말에는 비율의 원리, 불 조절, 넘어가는 신호가 있다. 둘이 다른 곳이 세 군데 있다.

## 어떻게 가져왔나

| | Claude (claude.ai) | Gemini | ChatGPT |
|---|---|---|---|
| 도구 | 데스크톱 앱 내장 브라우저로 영상 페이지를 열어 설명란을 펼치고 스크립트 패널을 읽음 | 유튜브 연동으로 자막과 기본 정보 | Firecrawl로 설명란과 한국어 자동 자막(시각 포함) |
| 설명란 | 읽음 | **읽지 않음**(설탕 분량을 자막에서만 찾음) | 읽음 |
| 자막 | 자동 자막, 시각 포함 | 자동 자막 | 자동 자막, 시각 포함 |
| 화면·음성 | 보지 않음 | 보지 않음. 요청받자 못 한다고 하고 기사(위키트리)로 대조 | 보지 않음. 물었을 때 그렇게 밝힘 |
| 걸림돌 | 웹 읽기 도구는 두 번 실패. 데스크톱 앱이 켜져 있어야 함 | 없음 | 외부 도구 필요 |

## 각자 잘한 것

- **Gemini**: 가장 빨리, 가장 읽기 쉽게. 비율 원리를 앞에 세운 구성. 한계를 물었을 때 숨기지 않았고 다른 길(2차 자료)을 스스로 찾았다.
- **ChatGPT**: 단계마다 영상 시각. 설명란과 시연의 차이를 구분. 어떤 문장이 자기가 덧붙인 것인지 설명할 수 있었다.
- **Claude**: 출처끼리 다른 곳과 추정값을 처음부터 표시. 흐리게 들린 재료(깨)를 지우지 않고 남김.

## 규칙으로 옮긴 것

| 본 것 | 규칙 |
|---|---|
| 자막만 보면 분량을 놓친다 | 정리 규칙 R-03: L0와 L1을 늘 같이 |
| 2차 자료가 분량의 출처가 됐다 | R-01: 숫자는 1차 출처에서만. 계약과 DB가 막는다 |
| 다른 곳을 하나로 합쳤다 | R-04: `conflicts`에 둘 다 |
| 덧붙인 기준이 본문에 섞였다 | R-07: `editor_tip`, `suggested_*`로 분리 |
| 시각이 있으면 바로 확인된다 | R-18: 단계마다 `video_start_seconds` |
| 나눠 넣는 재료를 놓쳤다 | R-14: `uses.portion` |
| 못 본 것을 먼저 말하지 않았다 | R-08: `not_checked`, `gaps` |
| 원리를 따로 세우니 읽기 좋다 | R-21: `principles` |
| 단계가 6개면 읽기 쉽고 12개면 따라 하기 쉽다 | 화면에서 묶어 보이기(R3 설계에서: 12단계를 큰 단계 4~6개로 접기) |

## 아무도 하지 않은 것

화면 글자와 장면 보기(L3), 음성 직접 받아쓰기(L2). 이 영상은 설명란이 충실해서 필요 없었다. 쇼츠와 릴스에서는 필요하다. 수집 단계를 L0~L4로 나눈 까닭이다.

## 다시 재는 방법

수집 스킬이 바뀌면 이 영상으로 다시 돌려 `contract/examples/youtube-AkX6uA4BaDs.json`과 대조한다. 대조 항목: 재료 15가지의 숫자, 대파·깻잎 나눠 넣기, 충돌 세 군데, 단계별 시각(±15초). 쇼츠와 릴스 예시는 R6에서 하나씩 더한다.
