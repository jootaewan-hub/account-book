# 레시피: 쿡앱(mise)에서 가져올 것

> **2026-11-18 브레인스토밍으로 일부가 낡았다.** 바뀐 내용과 낡은 곳은 `tracking/brainstorm.md`에 있고, 그 문서가 우선한다. 설계 문서가 승인되면 이 문서를 고친다.

`jootaewan-hub/cookapp-claude`(이름 mise)를 2026-11-18에 읽고 정리했다. 마지막 커밋은 2026-06-04다.

## 쿡앱은 어디까지 갔나

`docs/STATUS.md`(2026-06-01 기준) 요지:

- 재료 사전 약 1,558개, 레시피 88,907건(영문 RecipeNLG 84,142 + TheMealDB 472 + 한식 4,293), 재료 성질·궁합 설명, 냉장고 재료로 만들 수 있는 요리(`/cook`), 레시피 상세의 "있음/사야 함" 대조, 한·영 화면까지 만들었다.
- 남은 것은 배포(M7)였다: Cloudflare Pages + **Typesense 검색 서버 공개 호스팅**. 데모도 로컬 검색 서버를 띄워야 돌았다.

멈춘 까닭에 대한 판단(추측입니다): 검색 서버를 늘 켜 두어야 하는 구조, 8만 건이 영문이라 번역이 따라붙는 자료, 풍미 과학까지 넓힌 범위가 두 사람이 쓰는 앱에는 무거웠다. 기능이 모자라서가 아니라 운영할 것이 많아서다.

## 방향: 목표는 살리고 구조는 바꾼다

"가진 재료로 뭘 할 수 있나"는 그대로 가져온다. 바뀌는 것:

| | 쿡앱 | 레시피 부분 |
|---|---|---|
| 레시피 | 공개 자료 8만 9천 건 | 우리가 담은 레시피(수십~수백 건). 필요하면 공공 한식 4천 건을 더한다 |
| 검색 | Typesense 서버 | Postgres 함수 하나(`recipe.cookable`) |
| 가진 재료 | 브라우저에 저장한 냉장고 목록 | 가구 단위 `recipe.pantry`. **장보기에서 산 것과 영수증 품목이 후보로 들어온다** |
| 모자란 재료 | 보여 주기만 | 장보기 목록에 담기 |
| 운영 | 서버 두 개 | 새 서버 없음 |

가계부·장보기에 이미 "무엇을 샀는지"가 있다는 점이 쿡앱에는 없던 것이다.

## 가져오지 않을 것

| 쿡앱의 것 | 까닭 |
|---|---|
| Typesense, e5 임베딩, 하이브리드 검색 | 늘 켜 둘 서버가 필요하다. 수백~수천 건에는 필요 없다 |
| RecipeNLG 84,142건, TheMealDB 472건 | 비상업 조건의 영문 자료. 번역이 필요하고 우리 집 요리와 거리가 있다 |
| 풍미 과학(Ahn 2011, FlavorDB, FlavorGraph), 궁합 PMI, 재료 성질 설명 | 조건이 붙은 자료가 섞여 있고, 레시피북에는 덤이다. 미뤄 둔다 |
| 단계 그래프 도식(React Flow), 한·영 전환, 재료 허브 | 범위 밖 |
| 영양(국표성분표, USDA) | 장보기 성분 탭이 식약처 자료를 이미 쓴다. 필요하면 그쪽과 잇는다 |

## 사전 옮기기

1. PC의 쿡앱 폴더에 `data/normalized/`가 남아 있는지 본다(`ingredients_dict.generated.jsonl`과 그 뒤 단계 산출물). 저장소에는 씨앗 10줄과 보조 표만 있다. **확인 필요.**
2. 남아 있으면: 한식 재료(식약처·농진청에서 온 것, 가공 재료 씨앗, 신규 28종)만 골라 `id, name, name_en, aliases, category, broader`로 내보낸다. 영양·화합물·궁합 칸은 가져오지 않는다. 글로벌 영문 재료는 뺀다.
3. 남아 있지 않으면: 쿡앱 파이프라인을 다시 돌리지 않는다(키 세 개와 원천 파일이 필요하다). 대신 **필요할 때 늘리는 사전**으로 시작한다. 우리가 담은 레시피에 나온 재료와 장보기 분류 사전의 낱말에서 시작해, 못 맞춘 재료가 검토에 뜰 때마다 사람이 확인하고 더한다(`origin = 'added'`).
4. 어느 쪽이든 사전의 대분류 14종과 장보기의 분류 11종(정육, 수산, 채소, 과일, 유제품, 계란, 가공, 냉동, 음료, 생활용품, 기타)을 잇는 표를 만든다. 장보기에 담을 때 분류가 맞아야 한다.

사전 자료의 출처는 식약처·농진청 공개 자료(공공누리 제1유형·제한 없음)와 직접 만든 표다. 넣을 때 출처 표시를 문서에 남긴다.

## 가진 재료를 어떻게 아나

| 길 | 방법 | 단계 |
|---|---|---|
| 직접 | "뭐 해 먹지"에서 재료를 고른다. 소금·설탕·간장 같은 것은 "늘 있음"으로 한 번만 | R7 |
| 장보기 | 장보기에서 "샀음"으로 바뀐 품목을 사전에 맞춰 후보로 올리고, 사용자가 확인하면 들어간다 | R7 |
| 영수증 | 가계부 영수증 품목도 같은 방식 | R7 뒤 |
| 다 씀 | 요리했다고 표시하면 쓴 재료를 "아직 있나요?"로 묻는다. 자동으로 지우지 않는다 | R7 뒤 |

확인 필요: 장보기 품목 이름("비비고 왕교자 1.05kg")이 사전에 얼마나 맞는지. 상품명에서 재료 낱말을 뽑는 일은 장보기의 분류 사전(`src/grocery/lib/categories.ts`, `parse.ts`)이 이미 하고 있어 그것을 쓴다.
